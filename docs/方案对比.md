# 三形态方案对比：Skill / 网页应用 / 手机应用

> 三个形态跑的是同一套"图库匹配"内核，差别在于"谁在使用、在哪里使用、改什么最快"。
> 本文从三个形态的**真实使用链路**出发做对比，而不是比较技术栈完不先进。

## 0. 先有个前提：为什么不用"去手写"

主流方案（腾讯云试卷擦除、Mathpix、有道智云、开源 `wttwins/wrong-notebook`）都是：
**识别 → 去手写 → 排版**。去手写是整条链路里最贵且最不稳的一步，擦不干净就是复习时的二次污染。

本项目的选择是：**不去手写，而是匹配图库**。照片只用来抽指纹（数值/公式/题干开头），
命中图库后直接取图库里的纯净原题图当作题面——题面从未被拍摄，也就无从被写脏。

代价转移得很明确：省下了每题的去手写成本，代价是需要提前建一份图库。

## 1. 三个形态的定性对比

| 维度 | Skill（错题整理成册） | 网页应用 | 手机应用（PWA） |
|---|---|---|---|
| 谁用 | Agent 使用者（说一句话） | 坐在电脑前整理的人 | 在教室里当下拍的人 |
| 入口 | 对话里说"整理这些错题" | 双击 `web/index.html` | 添加到主屏，像 App 一样点开 |
| 依赖 | Python + Playwright + Chromium | 一个浏览器，零后端 | 一个浏览器 + serviceWorker |
| 拍照 | 由用户提供照片/指纹 | 可选（支持上传抽 dHash） | 主力（`capture="environment"` 直调相机） |
| 输出 | A4 PDF（带四项自检） | 打印 / 导 PDF / 导 notebook.json | 打印 / 导 PDF |
| 改东西的速度 | 改 `scripts/` 与 `references/` | 改一个 HTML 文件 | 改同一个模板 + 重打包 |
| 数据存哪 | 用户本地目录 | localStorage（浏览器） | localStorage |
| 适合做重活 | ✅ 批量、分学科分册、自检 | ✅ 批量核对、改知识点与错因 | ❌ 屏幕小，改字段麻烦 |
| 适合当场记录 | ❌ 要回到电脑 | ⚠️ 可用但不在身上 | ✅ 随手拍 |

## 2. 逐个形态的实话

### 2.1 Skill：最适合"结果要能交出去"

优势：

- **真能出成品**：脚本化管线（建索引 → 匹配 → 合卡 → 出 PDF + 自检），不依赖对话一段段生成。
- **可验证**：`--verify` 四项硬检查 + 负向测试，能证明它不是永远打印 PASS。
- **可复用**：参考文档写清了词表、阈值、版式规格，下次换题目不用重新发明。

劣势：

- 需要一台能跑 Python/Chromium 的环境。手机上做不了。
- 识别环节仍要外接多模态模型（本仓库不内置 Key）。

### 2.2 网页应用：最适合"批量核对与修补"

优势：

- 零部署：一个 250KB 的单文件，双击就开，断网也能用。
- **改字段舒服**：知识点点选、错因下拉、错解/正解可编辑——这是 Skill 里改 JSON 才能做到的。
- 同一套打分公式（JS 与 Python 权重完全一致），结果可互相验证。

劣势：

- 数据在 localStorage，换浏览器/清缓存就没了（需手动导 notebook.json）。
- 排版能力弱于 Skill：打印依赖浏览器 `@page`，精细控制不如 Playwright 出 PDF。

### 2.3 PWA：最适合"当场记录"

优势：

- `capture="environment"` 直接调相机，拍完就匹配，不用回电脑。
- 可添加到主屏、离线可用（serviceWorker 缓存页面）。

劣势：

- **它依然是网页**：iOS 上 PWA 的存储与后台能力受限，长期当笔记工具用会疼。
- 手机上改知识点/错因很难用，真整理还得回到网页版或 Skill。

## 3. 该选哪个：按场景给结论

| 你的场景 | 选它 | 理由 |
|---|---|---|
| 每周把一周错题整理成一本、要打印贴本子 | **Skill** | 唯一能稳定输出"单题不跳页 + 带裁切线"的 A4 PDF |
| 已经有一堆错题，需要逐题核对知识点/错因 | **网页应用** | 编辑体验是三个里最好的 |
| 考完试当场想把错题存下来 | **PWA** | 相机入口最短 |
| 想自己改阈值/加学科/改版式 | **Skill** | 参数集中在 `references/`，改一处生效 |

如果只能选一个长期用：**Skill 负责"出成果"，网页版负责"修数据"，两者搭配**。
PWA 是入口，不是主力——它的价值在于降低"拍照记录"这一下的心理成本。

## 4. 三者共享的东西（避免重复造轮子）

| 共享项 | 位置 |
|---|---|
| 打分公式 `0.45 数值 + 0.30 公式 + 0.20 文本 + 0.05 视觉` | `scripts/match.py` 与 `app_client.js` |
| 阈值 auto≥0.80 / confirm≥0.45 | 同上 |
| 知识点与错因受控词表 | `references/error-taxonomy.md` |
| 卡片版式 | `assets/card_template.html`（PDF）与 `app_client.js`（屏幕） |
| 图库索引格式 | `references/gallery-schema.md` |

## 5. 与其他现成方案的取舍

| 方案 | 它怎么做 | 我们的不同 |
|---|---|---|
| 腾讯云拍照批改 | 五步：切边增强→切题→识别→批改→坐标回显；切题约 0.2 元/次、手写擦除 0.15 元/次起 | 不在线、不按次付费；但需要自己建图库 |
| Mathpix | 纯 OCR，$0.002/图 | 它输出 LaTeX 文本，我们输出可直接打印的卡片 |
| 有道智云整题识别 | 0.15 元/次起（阶梯至 0.05） | 同上；且我们不依赖它的公式准确率 |
| `wttwins/wrong-notebook`（853★, MIT） | AI 去手写 + 挂课标树 + 三态复习 + 艾宾浩斯 | 它胜在复习调度完整，我们胜在题面 100% 不会被擦脏 |

一句话：**它们是"识别服务商"或"完整错题本系统"，我们是"一个选择：不给题面动刀"。**

## 6. 如果继续做，优先级怎么排

1. **接真实识别**（多模态抽指纹）——当前唯一让数据变成真的的一步。
2. **建图库工具链**（教材 PDF 切题 + 批量写 meta）——命中率的天花板在这里。
3. **复习调度器**（1/2/4/7/15/30）——PDF 上已经印了日期，差一个能提醒的调度器。
4. **公式渲染**（接 KaTeX）——数学题目前靠 `<sup>/<sub>`，上限很低。
