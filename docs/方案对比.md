# 方案对比：Skill / 网页应用 / 手机应用

> 三个形态都已跑通（见 `docs/实测报告.md`），这里只谈取舍。结论前置：
> **Skill 做内核验证与出 PDF；网页端做整理台；手机端只做"拍完即走"。不要三端都做全功能。**

## 一、三端横向对比

| 维度 | Skill | 网页应用 | 手机应用（PWA） |
|---|---|---|---|
| 上手成本 | 会说话就行（"把这些错题整理成册"） | 双击 HTML，无需部署 | 加到主屏，像个 App |
| 依赖 | Python + playwright + pillow | 只要浏览器 | 只要浏览器（安装需 HTTPS/localhost） |
| 首次可用时间 | 5 分钟（装好依赖即可） | 0（文件已在仓库里） | 0（但"安装"需要托管到 HTTPS） |
| 最适合的动作 | 批量出册、改版式、跑自检 | 校对、改知识点/错因、统计、导出 | 拍照入库、路上查看 |
| 不适合的动作 | 精细拖拽排版、可视化编辑 | 随手拍照（手机浏览器体验差） | 大屏整理、批量改标签 |
| 数据存放 | 本地文件（JSON + PDF） | localStorage，可导出 JSON | localStorage，可导出 JSON |
| 多端同步 | 靠文件（网盘/Git） | 手动导出导入 | 手动导出导入 |
| 迭代成本 | 改 prompt / 改脚本，无需发版 | 改模板重建 HTML | 同网页端 |
| 分发 | 每台机器装一次 Skill | 发一个 HTML 文件/挂个静态托管 | 需托管 + 安装引导 |
| 现状 | ✅ PASS（含 4 项自检 + 负向测试） | ✅ PASS（6 题入库、打印 3 题/页） | ✅ PASS（移动视口 390×844） |

## 二、为什么 Skill 应该先做

Skill 承担的不是"另一个入口"，而是**内核的可验证性**：

- 匹配阈值、词表校验、分页规则、裁切线，全部落成脚本里的硬约束，改一次全端生效；
- `--verify` 四项自检 + 负向测试，保证"看起来对了"和"真的对了"是两件事；
- 不需要账号、不需要部署、不需要备案，先在真实错题上验证命中率。

**一句话：Skill 是底座，两个 App 是它的两个视图。** 反过来做（先做 App）会陷入"界面很好看但匹配不准"的死局。

## 三、网页应用与手机应用的边界

同一个模板生成两个文件，差别只有布局与交互密度：

| | 网页（1280px） | PWA（390px） |
|---|---|---|
| 布局 | 双栏信息密度，卡片可展开编辑 | 单列，卡片只读 + 点开编辑 |
| 拍照入口 | `<input type=file>`（桌面拖拽更顺） | `capture="environment"` 直接调后置摄像头 |
| 主按钮 | 导出 PDF / 导出 notebook.json | 拍照 → 命中 → 卡片 |
| 打印 | 主力场景（A4，3 题/页，裁切角标） | 次要（应急） |
| 典型用法 | 考完当天把 8 张照片一次整理完 | 考场上/回家路上先拍下来，回家再整理 |

## 四、与开源方案 wrong-notebook 的分工

| | wrong-notebook（社区主流做法） | 本仓库 |
|---|---|---|
| 干净题面怎么来 | AI 识别 + **去手写**（SVG 重绘/擦除） | **图库原图匹配**（命中有干净图） |
| 成本结构 | 每次都要跑识别，按次计费 | 命中即零识别成本，未命中才退化 |
| 主要风险 | 擦不干净 → 题面污染 | 图库没有 → 命中失败 |
| 额外能力 | 知识点挂课标树、三态复习、变式题 | 无（当前只做整理与出册） |
| 适合谁 | 想要"一整套学习系统" | 想要"打印出来能贴本子"的纸质派 |

**两者不冲突**：图库匹配做"干净题面"，wrong-notebook 的复习调度逻辑可以后挂。真要合体，
优先借它三态复习（待复习/复习中/已掌握）+ 1/2/4/7/15/30 的调度，而不是借它的去手写。

## 五、如果只留一个

| 你的真实诉求 | 建议保留 |
|---|---|
| 我只要打印出来贴笔记本 | **Skill**（出 PDF 最直接） |
| 我要看统计、按知识点筛题、组卷 | **网页应用** |
| 我要在手机上随拍随记 | **PWA**，但必须配一个导出通道（否则数据死在手机里） |
| 我想长期维护这个项目 | **三个都留**，但只允许内核在 `skill/scripts` 里演进，前端不写业务逻辑 |

## 六、下一步的优先级

1. **接真实识别**（唯一必须补的一环）：一条多模态调用 → 指纹 JSON，替换 `demo/photos/*.features.json`。
2. **图库冷启动**：教材/教辅 PDF 批量切图建 300 题索引，命中率预计从 0 到 60%–75%。
3. **复习调度**：`due` 字段 + 今日队列，这是让错题本从"档案"变成"训练"的唯一开关。
4. 多端同步：一个 200 行的 Worker + D1 即可，不要上全套后端。
