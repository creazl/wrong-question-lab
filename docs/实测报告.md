# 实测报告

> 环境与数据都可复现：`tools/make_demo.py` 造样本，四个脚本跑链路，`tools/e2e_check.py` 做回归。

## 一、环境

| 项 | 值 |
|---|---|
| OS | Linux (vm) |
| Python | 3.12.11（pillow、imagehash、playwright） |
| 浏览器 | Chromium 146（`/usr/local/bin/chromium`，Playwright 驱动） |
| 字体 | Noto Serif / Sans CJK SC |
| 数据 | 6 道合成题（化学 2、物理 2、数学 2），题面由 Chromium 渲染 |

## 二、样本怎么造（为什么可信）

- **图库图**：HTML 渲染的印刷体题面，1500×260px 左右，纯白底（实测背景像素 255，PDF 里不会发灰）。
- **"手机照片"**：把图库图放进 A4 纸、桌面灰底 + 投影，**随机旋转 −3.4°～+3.1°**，
  叠一层红笔手写答案（`答案：C` 之类）+ 一句"过程略…"，再以 JPEG quality 58 压缩。
  也就是说：匹配器面对的是**歪斜 + 手写 + 有损压缩**的输入，不是干净图。
- 指纹由 `make_demo.py` 预置（模拟多模态抽取），数值/公式取自题面原值。

## 三、结果

### 3.1 匹配

| 照片 | 命中 | 分数 | 动作 | 领先量(gap) |
|---|---|---|---|---|
| q_hx_0001 | q_hx_0001 | 0.950 | auto | 0.650 |
| q_hx_0002 | q_hx_0002 | 0.815 | auto | 0.530 |
| q_sx_0001 | q_sx_0001 | 0.792 | confirm | 0.679 |
| q_sx_0002 | q_sx_0002 | 0.809 | auto | 0.806 |
| q_wl_0001 | q_wl_0001 | 0.784 | confirm | 0.672 |
| q_wl_0002 | q_wl_0002 | 0.787 | confirm | 0.787 |

- **命中率 6/6 = 100%**，top1 全部正确。
- 3 题落在 `confirm`（0.45–0.80）区间。原因不是匹配错，而是**指纹里少了一项文本命中**：
  `stem_keywords` 只给题干前 12 字，而 `text_jaccard` 对短串很敏感，导致总分被压在 0.80 以下。
  这不是调阈值能解决的问题——按协议，这三题就该让人点一下确认（3 次点击的成本远低于换错题的风险）。
- `gap` 全部 ≥ 0.53，说明**没有近似题干扰**，候选区分度足够。真正的风险场景（图库里有同一题的变式）
  在本次样本里没有覆盖，属于已知盲区。

### 3.2 耗时

| 步骤 | 耗时 |

按线性外推，300 题的图库建索引约 15s，单次匹配 < 0.1s（纯本地计算，无网络）。

### 3.3 PDF 自检

`render_pdf.py --verify` 四项：

```
[render_pdf] 6 题 -> demo/output/错题本-演示.pdf
[verify] PASS · 问题 0 处
```

覆盖：单题跨页 = 0（卡片实测高度均 < 277mm 可用高度）、重复题号 = 0、空题面 = 0、词表外知识点 = 0。

**负向测试**（证明自检不是摆设）：往 `notebook.json` 里故意塞一个 `综合/其他` 标签 + 一个空题面：

```
[render_pdf] no_image: ['q_hx_0002']
[render_pdf] vocab_out: ['q_hx_0001:综合/其他']
[verify] FAIL · 问题 2 处
exit = 1
```

## 四、踩到的坑（都已修）

| 坑 | 表现 | 修法 |
|---|---|---|
| Playwright 自带浏览器缺失 | `Executable doesn't exist ... chrome-headless-shell` | 指定系统 `chromium` 的 `executable_path` |
| `file://` 图片不加载 | 照片里题面是一个破图图标 | 改 base64 内联 |
| 词表校验假通过 | `vocab()` 返回 0 条，任何标签都"合规" | 按空白切分 token + 全大写缩写也计入；并加负向测试 |
| 标签命名漂移 | 演示用 `化学键/键角`，词表是 `物质结构/键角` | 演示数据对齐词表命名（这正是校验该抓的问题） |
| 候选缩略图不可辨 | 5.8:1 的题面图缩成一条线 | `object-fit: cover` 裁切 |
| PDF 白底发灰 | 大图被 Skia 转 JPEG | 降采样到 1500px 宽 + PNG（实测输出像素 255） |

## 五、没做的（别当成已完成）

1. **真实识别未接入**：本仓库不含任何 OCR / 多模态 API 调用，指纹来自预置 JSON。
   这是唯一能让"6/6"变成"真实世界可用"的关键缺口。
2. **复习调度未实现**：PDF 上印了 1/2/4/7/15/30 天，但没有队列、没有提醒。
3. **图库冷启动未做**：现有图库只有 6 题，真实使用需要 300 题量级（教材/教辅切图）。
4. **近似题干扰未测**：同一题的变式在图库里并存时，`gap` 会显著变小，需要真实数据验证。
5. **LaTeX 未接**：数学公式走 HTML `<sup>/<sub>`，复杂公式（矩阵、积分）会失真。

## 六、下一步该怎么测

1. 拿 20 张真实错题照片（含歪斜、有手写）→ 接一条多模态调用 → 看真实分布的分数与 `confirm` 比例。
2. 用 300 题图库重跑，记录命中率与"未命中清单"，那份清单就是补库优先级。
3. 把同一题的 3 道变式放进图库，专门测 `gap` 塌陷情况，再决定是否加"数值唯一性"前置校验。
