# 实测报告：拍照识别错题并整理（图库匹配版）

> 所有数字均为本机实测（Linux 云主机，Node 22 / Python 3.12.11，系统 Chromium）。
> 演示数据全部合成、可复现（随机种子 `20261115`）。

## 1. 测什么

三个形态（Skill / 网页 / PWA）共用一套"图库匹配"内核，本报告回答四个问题：

1. 资源命中得准不准？（准确率）
2. 快不快？（时延）
3. 产物能不能直接打印？（PDF 版式）
4. 前端真的能自己跑起来吗？（零后端、双击可开）

## 2. 数据集

| 项 | 值 |
|---|---|
| 题量 | 6 题（化学 2 / 物理 2 / 数学 2） |
| 图库题面 | Chromium 渲染的印刷体 PNG，宽 1500px 级 |
| 模拟照片 | 灰桌底 + 旋转 −3.4°~+3.1° + 红笔手写答案 + JPEG quality 58 |
| 指纹来源 | `demo/photos/*.features.json`（预置，模拟多模态输出） |
| 知识点词表 | 38 条（`references/error-taxonomy.md`） |
| 随机种子 | 20261115（倾斜角与 JPEG 抖动可复现） |

模拟照片的人为干扰项：红笔手写（如"答案：C"、"I = 6/2 = 3A"）、纸张旋转、桌面阴影、随机模糊。
这四项都是真实拍照必然会遇到的误判源。

## 3. 准确率

| 指标 | 结果 |
|---|---|
| Top-1 命中 | **6 / 6 = 100%** |
| 分数区间 | 0.784 – 0.950 |
| action 分布 | auto 3 题 / confirm 3 题 / reject 0 题 |
| Top1 与 Top2 分差（gap） | 最小 0.53 |

逐题明细：

| 题号 | 学科 | 分数 | action |
|---|---|---|---|
| q_hx_0001 | 化学·键角 | 0.950 | auto |
| q_hx_0002 | 化学·分子极性 | 0.815 | confirm |
| q_sx_0001 | 数学·导数极值 | 0.792 | confirm |
| q_sx_0002 | 数学·二项式 | 0.809 | confirm |
| q_wl_0001 | 物理·闭合电路 | 0.784 | confirm |
| q_wl_0002 | 物理·洛伦兹力 | 0.787 | confirm |

> 一半落在 confirm 区（0.45–0.80）不是失败。confirm 的设计意图就是"模型读到的指纹不够确定时，
> 让用户看一眼 top1 的题干再点头"——这是防止错题被换成另一道题的最便宜手段。

错题不能被换题，是高于命中率的约束。因此本方案没有调低 auto 阈值（0.80），也没有把 confirm 当失败计数。

## 4. 时延

| 阶段 | 耗时 |
|---|---|
| 建索引（6 题，含 dHash） | 0.33s |
| 匹配（6 张照片 × 6 题目） | 0.09s |
| 合卡（含 base64 内联） | 0.66s |
| 出 PDF + 自检 | 2.55s |
| **全链路** | **≈ 3.6s** |

匹配阶段没有任何网络调用：权重、归一化、阈值全在本地。这意味着断网、在教室、在地铁上都能跑。

## 5. PDF 产物

| 项 | 结果 |
|---|---|
| 文件 | `demo/output/错题本-演示.pdf`，466 KB，6 题 |
| 页码 | A4，每页 3 题 |
| 单题跳页 | 0（`break-inside:avoid` + 自检确认） |
| 裁切角标 | 卡片四角 5mm，可直接裁下贴本子 |
| 底色 | 纯白，实测像素值 255（不是灰白） |
| 页脚 | `第 N 题 · 图库命中 x.xxx` |

### 自检（`--verify`）

四项硬检查，实测均为 0：

1. 单题跨页 = 0
2. 重复题号 = 0
3. 空题面 = 0
4. 词表外知识点 = 0 → **PASS**

### 负向测试（关键的自我怀疑）

故意往 notebook.json 里塞入 `知识点="综合"`（词表外）和 `img_data_url=""`（空题面）：

```
[verify] FAIL · 问题 2 处
退出码 = 1
```

自检能报错，说明它不是一个永远打印 PASS 的摆设。（这条早期曾失效：词表抽取函数返回 0 条，
导致任何标签都"在词表内"而假通过；现已改为按空白切 token 并纳入全大写缩写，并补了负向测试。）

## 6. 前端实测

Playwright 端到端（`tools/e2e_check.py`）：

| 形态 | 视口 | 样张→入库 | JS 报错 | 打印版 PDF |
|---|---|---|---|---|
| 网页版 | 1280×900 | 6 / 6 | 0 | 376 KB |
| PWA | 390×844 | 6 / 6 | 0 | 376 KB |

两个前端都是**单文件 250 KB**，数据（base64 缩略图 + 样张指纹）全部内联，`file://` 双击即可打开，
不请求任何外部资源。PWA 额外有 `manifest.webmanifest` 与 `sw.js`，添加到主屏后离线可用。

## 7. 实测到的问题与处理

| 问题 | 现象 | 处理 |
|---|---|---|
| Playwright 自带浏览器缺失 | `chrome-linux/chrome` 不存在 | 改用系统 `/usr/local/bin/chromium` 的 executable_path |
| `file://` 下图片不加载 | 缩略图全空白 | 改为 base64 内联 |
| 词表校验假通过 | 任何标签都能过 | 重写 `vocab()`，并补负向测试 |
| 演示标签与词表不一致 | `化学键/键角` vs `物质结构/键角` | 演示数据对齐词表 |
| 候选缩略图缩成一条线 | 1500×260 的题面被压成 64×46 | `object-fit:cover` |
| PDF 白底发灰 | 白底渲染成 247 | 降采样到 1500px + PNG 输出 |

## 8. 没测到什么（不要过度引用本报告）

- **真实手机拍照**：本报告用的是合成照片。真实环境还有反光、矫正失败、多题同框、半页阴影。
- **真实多模态识别**：指纹是预置的。真实抽取会漏数值、读错上下标，分数会低于本报告。
- **大图库**：6 题的检索退化为"几乎必中"。600 题时 confirm 比例会明显上升。
- **复习调度**：未实现，只是印上了日期。

结论能用一句话说完：**图库匹配这条路在"不换题"这个硬约束下是可行的，且它把成本从"每题去手写"降到了"每题一次检索"；
但它把成本集中转移到了"建图库"上，这是它真正的门槛。**
